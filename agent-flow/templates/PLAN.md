## 制御フロー（このフローの走り方）
<一気通貫か、フェーズ分割か。ゲートを置く位置とその理由。

 既定: 全フェーズ gate: none で draft PR まで一気通貫し、@pr の後に @pr-review で PR を自己レビューする。
 チェックポイントは「開いた draft PR ＋ 投稿された自動レビューコメント」— ローカルで黙って止まる approve
 ではなく、外的に観測可能な成果物に置く（端末を離れても完了が死蔵されない）。
 approve は不可逆な副作用（本番マイグレーション実行・デプロイ・外部送信）を持つタスクの手前にだけ置く。
 draft PR を開くこと自体は reversible なので approve の対象外。ゲートが無ければ run は end-to-end で走り切る。

 PR 作成後レビュー（既定 ON、trivial では省略可）: @pr の後に gate: none の @pr-review タスクを置く
 （レビューはタスクが実施）。指摘は重大度で振り分け、本PR対応は @fix、スコープアウトは follow-up issue
 （worktree 撤去後も残す）。曖昧なものだけユーザーに確認。

 engine（run の駆動方式）: subagent（既定）/ goal / ralph。
 ゲート、または @pr-review タスク（トリアージでユーザーに確認しうる）があれば subagent 確定。
 @pr-review が既定 ON なので既定 engine は subagent。@pr-review を外した完全 gateless かつ
 「会話出力で示せる単一終了状態」がある場合のみ goal/ralph が候補。
 - goal を選んだ場合: 完了条件（出力で示せる終了状態＋制約＋ターン上限）をここに明記 → run が `/goal` に渡す。
 - ralph を選んだ場合: 再投入プロンプト＋完了フレーズ＋max-iterations をここに明記 → run が `/ralph-loop` に渡す。>
